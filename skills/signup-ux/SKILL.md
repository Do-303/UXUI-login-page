# 가입 UX 규칙

브랜드와 상관없이 쓸 수 있는 규칙만 모았어요. 색·글자 크기·간격·문구 말투는 각 서비스의 가이드를 따라요.

## 1. 로그인 수단 고르기

| | 아이디 | 이메일 |
|---|---|---|
| 좋은 점 | 짧고 입력이 편해요 (특히 휴대폰) | 따로 외울 게 없고 연락 수단을 겸해요 |
| 약점 | 잊어버리기 쉬워요 | 길어서 입력이 귀찮아요 |
| 약점 메우기 | 본인인증으로 아이디 찾기 | — |

- 본인인증을 함께 쓰는 서비스라면 **아이디 + 본인인증**이 좋아요. 아이디를 잊어도 본인인증으로 찾고, 연락은 인증된 전화번호로 해요.
- 아이디 방식이어도 이메일은 **선택 항목**으로 받을 수 있어요.
- 아이디 규칙은 흔히 쓰는 틀을 따라요. 예: 5~20자, 영문 소문자·숫자·밑줄(`_`), 영문으로 시작, 숫자만으로는 불가.
- 대문자로 입력하면 오류를 내지 말고 소문자로 바꿔 주고, 칸 아래에 작게 알려 줘요.
- Supabase처럼 이메일 기반 인증 서비스에서 아이디 로그인을 하려면 아이디를 내부용 가짜 이메일(`아이디@서비스.local`)로 바꿔 저장하는 식으로 우회해요.

## 2. 필수 · 선택 표시

- 필수 칸은 라벨 옆에 `*`, 폼 위에 "* 표시는 필수 입력 항목이에요"를 한 번 적어요.
- 선택 칸은 라벨에 `(선택)`을 붙여요. 색이나 기호만으로 구분하지 않아요.
- 선택 칸 아래에는 **넣으면 무엇이 좋은지** 한 줄로 알려 줘요.

## 3. 입력 검사 타이밍 (가장 중요)

사용자가 아직 쓰는 중일 때 혼내지 않아요.

| 상황 | 동작 |
|---|---|
| 글자를 치는 중 | 검사하지 않아요. 빨간색 없음 |
| 칸을 벗어날 때 (다른 칸 클릭, Tab, Enter) | 처음 검사해요. 틀렸으면 오류 표시 |
| 오류가 뜬 칸을 고치는 중 | 맞게 되는 **순간 바로** 오류를 지워요 |
| 빈 칸 | 칸을 벗어나도 오류 없음. **제출할 때만** 필수 빈 칸을 오류로 |
| 선택 칸이 비어 있음 | 언제나 오류 없음 |

> 틀린 걸 알려줄 땐 늦게, 맞은 걸 알려줄 땐 빠르게.

- 코드에서는 첫 검사를 `blur`(칸에서 포커스가 빠지는 순간)에, 오류가 뜬 뒤의 재검사를 `input`에 걸어요.
- 한 칸의 검사가 다른 칸을 빨갛게 만들면 안 돼요. 중복확인 결과는 그 칸에만 보여요.
- 비밀번호 확인 칸은 **확인 칸을 직접 건드린 뒤에만** 일치 여부를 검사해요.
- 제출 시에는 첫 번째로 틀린 칸으로 포커스를 옮겨요.

## 4. 긴 입력은 단계별로 접기

칸이 많으면 한 화면에 다 펼치지 않고 한 단계씩 보여 줘요.

```
계정 정보를 입력해 주세요          ← 제목은 위에 고정
✓ 본인인증   홍길동 · 010-****-5678   수정
✓ 아이디     sample                 수정
──────────────────────────
비밀번호      [            ]
비밀번호 확인  [            ]
🏠 3 / 4 문에 자물쇠를 달아요        ← 진행 표시는 버튼 바로 위
[ 다음 ]
```

- 제목은 스크롤해도 위에 **고정**해요.
- 끝난 단계는 위로 밀어 사라지게 하지 말고 **한 줄로 접어서 남겨요.** 입력한 값이 계속 보여서 헷갈리지 않아요. "수정"을 누르면 다시 열려요.
- 함께 확인해야 하는 칸(비밀번호 + 비밀번호 확인)은 **같이 열리고, 둘 다 끝나면 같이** 접혀요.
- 지금 몇 번째 단계인지 보여 줘요. 예: "3 / 4". 위치는 **입력 칸 아래, 다음 버튼 바로 위**예요. 해야 할 입력이 먼저 보이고, 진행 정도는 버튼을 누르기 전에 확인해요.
- 진행 표시에 단계 이름("비밀번호")을 또 쓰지 않아요. 칸 제목과 겹쳐요. 대신 짧은 응원 문구나 그림(예: 집이 한 조각씩 지어지기)으로 바꿔도 좋아요.
- 단계마다 "이 값으로 할까요?" 팝업을 띄우지 않아요. 누를 게 늘어나요. 확인은 마지막에 한 번만 해요.

## 5. 가입 전 확인 팝업

"가입하기"를 누르면 입력한 내용을 한 번 보여 주고 확인받아요.

- 제목 예: "이 정보로 가입할까요?"
- 이름·휴대폰(일부 가림)·아이디·닉네임·이메일처럼 **다시 보면 좋은 값**만 보여 줘요.
- **비밀번호는 보여 주지 않아요.** "비밀번호는 보안을 위해 보여 드리지 않아요."
- 버튼은 `다시 볼게요` / `가입하기`. 닫기와 Esc는 `다시 볼게요`와 같아요.

## 6. 가입 직후 추가 질문은 팝업으로

가입에 꼭 필요하지 않은 질문(취향·관심사 등)은 가입 단계에 넣지 않고, 가입을 마친 뒤 팝업으로 물어요.

- 가입은 이미 끝난 상태라 건너뛰어도 손해가 없고, 단계 표시줄도 늘어나지 않아요.
- 건너뛰기 버튼을 꼭 두고, 닫기(X)와 Esc는 건너뛰기와 똑같이 동작해요.
- "나중에 마이페이지에서 바꿀 수 있어요."를 작게 알려 줘요.

## 7. 가입 · 로그인 직후 화면

- 첫 화면은 **다음에 할 일**을 권해요. 예: "쇼핑을 시작해 볼까요?" + `쇼핑 시작하기` / `추천 상품 보기`. 방금 들어온 사람에게 "로그아웃"을 큰 버튼으로 보여 주지 않아요.
- 가입 때 받은 정보(관심사·생활 이벤트 등)가 있으면 첫 문구를 그에 맞게 바꿔요.
- 로그아웃 · 회원 탈퇴는 화면 아래 구석에 작은 글자로 둬도 돼요. 단, **보이게** 둬요. 접힌 메뉴 깊숙이 숨기면 다크패턴이에요.

## 8. 본인인증

| | 단순 문자 인증 | 통신사 본인인증 |
|---|---|---|
| 확인하는 것 | 이 번호를 지금 갖고 있는지 | **이 사람이 누구인지** (이름·생년월일·성별) |
| 받는 값 | 전화번호 | CI(연계정보, 사람마다 하나인 고유 값), 생년월일 등 |
| 번호를 바꾸면 | 다른 사람으로 인식해요 | **같은 사람으로 인식해요** |
| 필요한 것 | 문자 발송 서비스 (유료) | 본인확인기관(NICE, KCB 등) 계약, 보통 사업자등록 필요 |

- **연락처만 확인**하면 될 때 → 단순 문자 인증
- **한 사람에 한 번**이 중요할 때 (신규 가입 혜택, 재가입 판별, 만 14세 확인) → 통신사 본인인증
  - 이메일은 여러 개 만들 수 있고, 전화번호는 해지된 번호가 다른 사람에게 다시 가서 둘 다 "같은 사람"을 보장하지 못해요.
- 인증 버튼 근처에 왜 하는지 짧게 적어요.
- 화면 흐름: 통신사 고르기 → 이름·생년월일·전화번호·인증번호 입력 → 인증 완료.

### 계정 존재 여부는 인증 뒤에만 (가장 중요)

입력만 해도 "이전에 쓰던 계정이에요"를 보여 주면, 남의 정보를 넣어 보기만 해도 그 사람이 서비스를 썼는지 알 수 있어요(계정 존재 여부 노출).

- 재가입 안내는 **본인인증을 마친 본인에게만** 보여요. 인증 전에 보여 줘도 되는 건 "이미 사용 중인 아이디예요" 같은 중복확인 정도예요.
- 인증한 정보를 고치면 인증을 풀고, 재가입 안내도 함께 닫아요.
- 중복 가입을 막으려고 탈퇴 뒤에도 CI 같은 값을 가질 땐 **알아볼 수 없게 바꾼 값(암호화·해시)** 으로만, **기간을 정해서** 보관하고 약관에 적어요.
- 실제 계약 없이 흐름을 보여 줄 때는 화면은 실제처럼, 동작은 가짜 결과를 돌려주게 만들고 "데모용 가짜 인증"이라고 분명히 적어요.

## 9. 약관 동의

```
┌ 약관 상자 ───────────────────────┐
│ ☐ 전체 동의                       │
│ ───────────────────────────────  │
│ ☐ (필수 약관들)            필수 보기│
│ ☐ (선택 약관들)            선택 보기│
└──────────────────────────────────┘
필수 항목만 동의                선택 해제
[ 다음 ]
```

- **전체 동의**만 상자 맨 위 체크박스로 둬요.
- **필수 항목만 동의**와 **선택 해제**는 상자 아래 **같은 줄**에 같은 모양의 작은 링크로 둬요 (왼쪽 필수만 / 오른쪽 해제). 체크박스 줄을 하나 더 만들면 전체 동의와 헷갈리고 상자가 길어져요.
- 각 약관은 **따로따로** 고를 수 있어요. '보기'를 눌러도 체크되지 않아요.
- 필수 약관이 모두 체크돼야 "다음"이 켜지고, 꺼져 있을 땐 아래에 이유를 한 줄로 알려 줘요.
- 본인인증으로 생년월일을 받으면 "만 14세 이상" 체크를 자동 확인으로 바꾸는 걸 검토해요.
- 가입 흐름에 새 질문을 넣으면 **개인정보 수집·이용** 약관에도 무엇을, 왜, 언제까지 보관하는지 넣어요. 민감할 수 있는 정보는 꼭 선택 사항으로 둬요.

## 10. 아이디 · 계정 찾기

| 경로 | 누가 쓸 수 있나 | 특징 |
|---|---|---|
| 본인인증 | 모든 회원 | 가장 확실해요. 기본 경로로 둬요 |
| 이메일 | 이메일(선택)을 넣은 회원만 | 본인인증이 귀찮은 사람에게 편해요 |

- 본인인증으로 찾으면 아이디 **일부를 가려서** 보여요. 예: `sam***e`
- 이메일로 찾으면 화면에는 "입력하신 이메일이 가입되어 있다면 메일을 보냈어요."만 보여요. 없는 이메일이어도 같은 문구예요.
- 비밀번호는 알려 주지 않고 **새로 만들게** 해요. 재설정 링크는 짧은 시간만, 한 번만 쓸 수 있게 해요.
- 너무 여러 번 시도하면 잠시 막아요.

## 11. 탈퇴 · 재가입

> 떠날 땐 쉽게, 돌아올 땐 따뜻하게.

### 탈퇴는 쉽게

탈퇴를 막거나 죄책감을 주는 디자인은 다크패턴(사용자를 속이거나 방해하는 디자인)이고, 법으로도 해지·탈퇴 방해를 규제하는 쪽이에요.

- 탈퇴 버튼을 찾기 쉬운 곳에 두고, **3번 클릭 안에** 끝나게 해요. 마지막 확인은 한 번이에요.
- 탈퇴 대신 고를 수 있는 길(예: 잠시 쉬어가기)은 **나란히 보여 주기만** 해요.

### 탈퇴 사유 + 해결 방법

- 사유는 선택 사항이에요. "선택하지 않아도 탈퇴할 수 있어요"는 제목 아래 **작은 글씨**로 둬요.
- 해결할 수 있는 사유를 고르면 그 아래에 **바로 가기 링크**를 작게 보여 줘요.
- 탈퇴 버튼은 **항상** 보여요. 문구는 "그래도"처럼 사용자를 탓하는 말 없이 "탈퇴할게요"로 담백하게 써요.

| 사유 예시 | 바로 가기 |
|---|---|
| 알림이 너무 많이 와요 | 알림 설정 |
| 개인정보가 걱정돼요 | 개인정보 관리 / 마케팅 동의 철회 |
| 당분간 쓸 일이 없어요 | 잠시 쉬어가기 (계정 일시정지) |
| 배송·교환·환불이 불만족스러웠어요 | 1:1 문의 |
| 원하는 상품이 없어요 | (없음) |
| 다른 계정으로 쓰고 있어요 | (없음) |
| 기타 | 직접 입력 |

### 보관은 동의받고, 불이익은 숨기지 않고

- 탈퇴하면 개인정보는 원래 바로 지워야 해서, 복원하려면 **탈퇴할 때 직접 선택**받아요. (보관해 주세요 / 모두 지워 주세요)
- 보관 기간이 지나면 자동으로 지워요.
- 재가입 시 받을 수 없는 혜택이 있으면 탈퇴 버튼 바로 근처에 알려요. 글씨는 작아도 **숨기지 않아요.**

### 재가입은 따뜻하게

- "혹시 돌아오신 건가요?"는 **본인인증을 마친 뒤에만** 보여요. 버튼은 `제가 아니에요` / `네, 맞아요`.
- "탈퇴"라는 단어를 앞세우지 않고 "이전에 이용하셨던 분" 처럼 순하게 써요.
- 보관 기간 안에 돌아오면 무엇이 남아 있는지 보여 주고, 복원할 항목을 **골라서** 불러오게 해요. 마감일도 보여 줘요.
- "새로 시작할게요"를 고르면 예전 내역은 바로 지워진다고 알려 줘요.
- 가입 직후 질문(취향, 생활 이벤트 등)은 다시 물어봐요. 이때 **지난번에 고른 답을 꺼내지 않아요.** ("지난번엔 결혼 준비로…" 같은 말 금지) 재혼·이별처럼 상황이 바뀌었을 수 있어서, 예전 삶의 일을 떠올리게 하지 않아요. "또 ~해요", "혼자 살게 됐어요"처럼 과거나 이별을 짐작하게 하는 선택지 문구도 피해요.
- 보관 기간이 지났거나 보관을 거부했으면 불러올 수 없다는 걸 한 번 짧게 알려 주고 바로 시작하게 해요.

## 12. 움직임 원칙

- 움직임은 장식이고, 정보는 언제나 글자로도 보여요.
- 오류 흔들림 같은 피드백은 0.3초 이내로 짧게 해요.
- 재미 요소는 가입을 **마친 뒤**(완료 화면, 팝업)에 둬요. 입력 중에는 방해하지 않아요.
- "동작 줄이기"(`prefers-reduced-motion`)를 켠 사람에게는 움직임 없이 바로 결과를 보여요.
- 웹에서 문이 열리는 모습은 CSS 3D(`perspective` + `rotateY`)로 만들면 가볍고 자연스러워요. 피그마에서는 3D가 없어서 문 폭이 줄어드는 키프레임으로 흉내 내요.

## 13. 접근성

**입력 칸**
- 모든 칸에 보이는 라벨을 둬요. placeholder(칸 안의 흐린 안내)만으로 라벨을 대신하지 않아요.
- 오류 문구는 `aria-describedby`로 칸과 연결하고, `aria-live`로 화면낭독기가 읽게 해요.
- 오류·성공은 색만이 아니라 글자로도 알려 줘요.
- 아이콘 버튼(눈 아이콘 등)에는 `aria-label`을 붙여요.
- 인증번호 칸은 `inputmode="numeric"`, `autocomplete="one-time-code"`.

**누르기 · 키보드**
- 누르는 영역은 높이 44px 이상. 글씨가 작은 링크도 마찬가지예요.
- 링크처럼 보여도 동작이 버튼이면 `<button>`으로 만들어요.
- 체크박스와 글자는 `<label>`로 묶되, '보기' 링크는 label 밖에 둬요.
- 라디오 묶음은 `fieldset` + `legend`로 만들어요.
- 팝업은 Tab이 팝업 안에서만 돌고, Esc로 닫혀요.
- 접힌 단계의 "수정"은 키보드로도 열 수 있어야 하고, 열리면 그 단계 첫 칸으로 포커스가 가요.

**색**
- 글자 대비 4.5:1 이상. 밝은 브랜드색 버튼 위 흰 글씨는 대비가 낮기 쉬워서 꼭 확인해요.
